---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# SPEC-002: Runtime State & Virtual Memory\n\n> This specification defines the in-memory representation of the system state during active execution.\n\n## 1. Volatile Memory Layout\n\n- **Static Region**: Core system contracts and immutable lookup tables.\n- **Heap Region**: Dynamic entity states and event buffers.\n- **Warden Guard Pages**: Memory regions isolated for capability verification.\n\n## 2. P-Script VM State\n\n```text\nVMState {\n    PC: uint64 (Program Counter)\n    Registers: [16]uint64\n    Stack: List<Value>\n    CapabilityRegister: uint64 (Current authority mask)\n    GasMeter: uint64\n}\n```\n\n## 3. Memory Safety Laws\n\n- **No Direct Pointers**: All references must go through the `EntityID` or `ResourceHandle` lookup tables.\n- **Temporal Isolation**: Memory allocated for event $E_n$ must be zeroed or reclaimed before event $E_{n+1}$ begins processing unless explicitly promoted to long-term state.\n- **Bounds Checking**: Every memory access is bounds-checked at the VM or Runtime level.\n\n--- \n*Refer to [SPEC-003: Ledger State](./SPEC-003-Ledger-State.md) for persistence laws.* \n
