---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Layering Rules\n\n> This document defines the strict layering architecture of PhoenixOS.\n\n## 1. Layer Definitions\n\n| Layer | Authority | Description |\n| :--- | :--- | :--- |\n| **Platform** | User/CLI | End-user interfaces and host OS integration. |\n| **Cognition** | Intelligence | Reasoning, memory, and prediction engines. |\n| **Governance** | Policy | Rule enforcement and truth verification. |\n| **Assurance** | Safety | Capability checking and security monitoring. |\n| **Foundation** | Primitives | Ledger, events, and core runtime. |\n\n## 2. Access Rules\n\n- **Strict Layering:** Layer $N$ can only call Layer $N-1$ directly. Bypassing layers is prohibited (e.g., Cognition calling Foundation directly).\n- **Contract Boundary:** All cross-layer calls must pass through a `contract` package.\n\n--- \n*Refer to [docs/MASTER_SYSTEM_MAP.md](../MASTER_SYSTEM_MAP.md) for the visual hierarchy.* \n
