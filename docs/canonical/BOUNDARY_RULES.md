---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# System Boundary & Governance Rules\n\n> This document defines the architectural boundaries and governance rules that prevent unauthorized authority expansion and maintain system integrity.\n\n## 1. Layering Rules\n\n| ID | Rule | Description |\n| :--- | :--- | :--- |\n| **LAY-001** | **Unidirectional Dependencies** | Dependencies must always flow downward according to the Master System Map. Circular dependencies between layers are forbidden. |\n| **LAY-002** | **Opaque Implementation** | Higher layers must only interact with lower layers through their defined `contracts` or `interfaces`. Direct access to internal structures is prohibited. |\n| **LAY-003** | **Enforced Isolation** | Modules within the same layer should have zero cross-dependencies unless explicitly permitted in the `MASTER_DEPENDENCY_MAP.md`. |\n\n## 2. Dependency Rules\n\n| ID | Rule | Description |\n| :--- | :--- | :--- |\n| **DEP-001** | **Explicit Imports** | All external dependencies must be vetted and pinned. Dynamic or un-versioned imports are disallowed in core modules. |\n| **DEP-002** | **No Third-Party Logic in Foundation** | The Foundation layer must have zero dependencies on non-standard libraries, except for foundational primitives (e.g., crypto, networking). |\n\n## 3. Extraction & Modularization Rules\n\n| ID | Rule | Description |\n| :--- | :--- | :--- |\n| **EXT-001** | **Clean Cut Lines** | Subprojects must be designed to be extracted into independent repositories. This requires zero-knowledge of sibling modules. |\n| **EXT-002** | **Interface-First Design** | Before implementing a cross-module feature, the interface must be defined in the `foundation/contracts` module. |\n\n## 4. AI Autonomy & Actuation Rules\n\n| ID | Rule | Description |\n| :--- | :--- | :--- |\n| **AUT-001** | **Intent-Only Cognition** | The Cognition layer can only output *Intent* objects. It cannot modify state or call actuators directly. |\n| **AUT-002** | **Warden Validation** | All AI-generated intents must pass through the Warden for capability and safety checks. |\n| **AUT-003** | **Self-Evolution Gating** | AI agents cannot modify the code of the Governance or Assurance layers. |\n| **AUT-004** | **L6 Self Evolution Limit** | L6 (Highest level) evolution MUST NOT write directly to Runtime, Ledger, or Warden. It must submit PR-equivalent events to the Evolution pipeline. |\n\n--- \n*Violation of these rules will result in a build failure or a runtime S1 exception.* \n
