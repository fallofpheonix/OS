---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Dependency Rules\n\n> This document defines the rules for inter-module and external dependencies within the Phoenix system.\n\n## 1. Internal Dependency Rules\n\n- **Downward Flow:** Dependencies must only flow from higher layers to lower layers as defined in `MASTER_SYSTEM_MAP.md`.\n- **Interface Dependency:** Modules should depend on `contracts` rather than specific implementations whenever possible.\n- **No Circularity:** Circular dependencies between modules or layers are strictly forbidden and will be caught by CI.\n\n## 2. External Dependency Rules\n\n- **Vetting Process:** All new external dependencies must be approved and recorded in the `DEPENDENCY_INVENTORY`.\n- **Pinning:** All dependencies must be pinned to specific versions (using `go.sum` or equivalent).\n- **Foundation Isolation:** The Foundation layer must have zero dependencies on non-standard libraries.\n\n--- \n*Refer to [BOUNDARY_RULES.md](./BOUNDARY_RULES.md) for global layering context.* \n
