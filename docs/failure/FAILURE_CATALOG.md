---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Failure Catalog & Recovery Architecture\n\n> This document catalogs known failure modes, their severity, and the architected recovery paths. \n> Phoenix is designed for graceful degradation and automated recovery.\n\n## 1. Severity Levels\n\n| Level | Name | Description | Action Required |\n| :--- | :--- | :--- | :--- |\n| **S1** | **Catastrophic** | Violation of Master Invariants. System integrity lost. | Emergency Shutdown / Manual Intervention |\n| **S2** | **Critical** | Core service (Ledger, Runtime) failure. | Automated Rollback / Recovery Mode |\n| **S3** | **Degraded** | Subsystem (Cognition, UI) failure. | Local Restart / Reduced Functionality |\n| **S4** | **Warning** | Non-critical error, transient. | Log & Alert |\n\n## 2. Failure Catalog\n\n| Code | Name | Severity | Invariant Violation | Recovery Path |\n| :--- | :--- | :--- | :--- | :--- |\n| **ERR-001** | State Divergence | S1 | INV-001 | Halt & Replay from last known good block. |\n| **ERR-002** | Unattributed Mutation | S1 | INV-002 | Isolate affected module; Audit Ledger. |\n| **ERR-003** | AI Actuation Bypass | S1 | INV-003 | Revoke AI capabilities; Warden Lockdown. |\n| **ERR-004** | Ledger Corruption | S1 | INV-009 | Restore from peer/backup; Resync. |\n| **ERR-005** | Determinism Breach | S2 | INV-007 | Re-execute block; Check hardware/concurrency. |\n| **ERR-006** | State Scribe Timeout | S2 | INV-005 | Force snapshot; Verify against Ledger. |\n| **ERR-007** | Warden Latency | S3 | - | Throttle Cognition requests. |\n| **ERR-008** | Prediction Drift | S4 | - | Re-train/Calibrate Cognitive models. |\n\n## 3. Recovery Paths\n\n### 3.1 Automated Rollback\nIn the event of a S2 failure during a state transition, the system must automatically revert to the state prior to the offending event. \n\n### 3.2 Replay Recovery\nIf state corruption is detected (S1), the system enters Replay Recovery mode. It will wipe the current memory and rebuild the state by re-processing the event log from the last validated checkpoint.\n\n### 3.3 Fail-Closed Protocol\nIf an invariant violation is detected and automated recovery fails, the system must "Fail-Closed": all external actuators are locked, and the system enters a read-only diagnostic state.\n\n--- \n*Refer to [docs/governance/BOUNDARY_RULES.md](../governance/BOUNDARY_RULES.md) for isolation strategies.* \n
