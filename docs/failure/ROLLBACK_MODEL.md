---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Rollback Model\n\n> This document defines the technical mechanism for state rollbacks in PhoenixOS.\n\n## 1. Transactional State\n- Every mutation event is treated as a transaction.\n- The `Runtime` maintains a "shadow state" during event processing.\n\n## 2. Rollback Mechanism\n- **Undo Log:** The State Scribe records pre-mutation values for every state change.\n- **Atomic Commit:** State changes are only promoted to "Permanent" once the event is successfully ledgered and validated.\n\n--- \n*Refer to [RECOVERY_PATHS.md](./RECOVERY_PATHS.md) for trigger conditions.* \n
