This document defines the bounded cycle architecture of PhoenixOS and the fundamental laws governing authority within the system.

## 1. Nested Shared Cycles
The Phoenix existence is defined by a hierarchy of contract-governed cycles:

- **Existence (Nucleus):** Instruction -> Capability -> Authority -> Ledger -> Replay -> Recovery.
- **Understanding (Cognition):** Fact -> Memory -> Knowledge -> Belief -> Prediction -> Reflection.
- **Adaptation (Crucible):** Hypothesis -> Simulation -> Verification -> Promotion.
- **Communication (Terminus):** Telemetry -> Visualization -> Explanation -> Human -> Feedback.

## 2. Authority Conservation Laws
1.  **Authority is Finite:** Power cannot be created; it is issued from Genesis or delegated via the Ledger.
2.  **Law of Conservation:** In any delegation, the sum of child authorities plus the remaining parent authority must equal the original parent authority.
3.  **Irreversible Attenuation:** A capability token cannot gain authority it was not explicitly delegated.
4.  **Evidence Dependency:** Authority is null and invalid if its lineage cannot be traced back to Genesis via verified events.

## 3. Cognitive Grounding
- **Fact vs. Belief:** Facts are Ledger-recorded events. Beliefs are high-confidence Knowledge graphs derived from Evidence.
- **Cognitive Sovereignty:** Reasoning traces are ledgered to ensure the *logical path* taken by Phoenix is reconstructible and auditable, even if the specific model weights are opaque.
- **Wisdom Invariant:** Wisdom is an abstraction of the World Model. If the World Model diverges from Reality (Prediction Error), Wisdom must be revised.

## 4. Genesis Invariants
- Genesis defines the **Root Identity** and the **Initial Mission**.
- Genesis is the immutable first block of the Ledger.
- If Genesis is corrupted, the system must fail-closed.
