---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# SPEC-007: Capability Model & Token Attenuation\n\n> This specification defines the capability-based security model for PhoenixOS.\n\n## 1. Capability Token Structure\n\n```text\nCapabilityToken {\n    ID: SHA256\n    Owner: IdentityID\n    Resources: List<ResourcePattern> (e.g., \"ledger/*\", \"runtime/kernel\")\n    Permissions: Bitmask (READ, WRITE, EXECUTE, DELEGATE)\n    Expiration: uint64 (Tick)\n    ParentToken: SHA256 (for traceability)\n}\n```\n\n## 2. Token Attenuation Laws\n\n- **Non-Escalation**: A delegated child token must have a subset of the permissions and resources of its parent token.\n- **Temporal Decay**: Tokens automatically expire after the `Expiration` tick and cannot be renewed without a new authorization event.\n- **Revocation**: The Warden can invalidate any token by ledgering a `RevocationEvent`, which updates the `AssuranceState`.\n\n## 3. Delegation Chain\n\n- Root Authority -> Governance Layer -> Subsystems (Warden, Mind) -> Tasks (P-Script).\n- Every `AuthorizedIntent` must include the full delegation chain for verification.\n\n--- \n*Refer to [docs/MASTER_INVARIANTS.md](../MASTER_INVARIANTS.md) for authority laws (INV-015, INV-018).* \n
