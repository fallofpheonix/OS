---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# SPEC-003: Ledger State & Consensus\n\n> This specification defines the format and consistency rules for the Phoenix Ledger.\n\n## 1. Block Structure\n\n```text\nBlock {\n    Header {\n        Height: uint64\n        Timestamp: uint64 (Logical Time)\n        PrevBlockHash: SHA256\n        MerkleRoot: SHA256 (Root of Event transactions)\n        ValidatorSignature: Signature\n    }\n    Transactions: List<Event>\n}\n```\n\n## 2. Consensus Laws\n\n- **Singular Timeline**: Only one block can exist at a given `Height`. Forking triggers an immediate S1 consensus breach.\n- **Validator Quorum**: Blocks must be signed by $2F+1$ validators in a PoA (Proof of Authority) cluster.\n- **Link Integrity**: Block $N$ must contain the SHA256 hash of the header of Block $N-1$.\n\n## 3. Immutability & Pruning\n\n- **Frozen History**: Blocks older than the `PruningHorizon` are archived to COLD storage but remain cryptographically linked.\n- **State Snapshots**: Periodic `SPEC-001` snapshots are ledgered as "Checkpoint Events" to allow new nodes to sync without replaying from Genesis.\n\n--- \n*Refer to [docs/MASTER_INVARIANTS.md](../MASTER_INVARIANTS.md) for ledger laws (INV-009, INV-010).* \n
