# Research backlog: R003 - Forensic Memory Snapshots & Credential Abuse

## 1. Metadata
*   **Experiment ID:** R003
*   **Subsystem:** DFIR / Process Memory
*   **Priority:** P1 (Memory Snapshots & Credential Abuse)
*   **Validation Status:** Proposed (Requires `CAP_SYS_PTRACE`)
*   **Risk Level:** Medium (Reading memory of other processes has security implications and can crash unstable processes)
*   **Pilot Mapping:** Pheonix MVP Forensic Runtime (`08_forensics/memory/`)

---

## 2. Objectives
Develop a lightweight volatile memory snapshot runtime capable of identifying process memory injection (e.g., shellcode) and harvesting memory dumps of suspected processes for credential abuse analysis.

---

## 3. Threat Path
*   **Attack Vectors:** LSASS/GDM credential dumping, reflective DLL injection, memory-only malware running from anonymous descriptors (e.g. `memfd_create`), and process hollowing.
*   **Threat Assumptions:** Attackers will encrypt active payloads in memory or quickly scrub secrets to avoid dump analysis.

---

## 4. Telemetry Source
*   **Production hooks:** `/proc/<pid>/maps` (memory segment permissions), `/proc/<pid>/mem` (raw memory bytes), and ptrace syscalls.
*   **Simulation hooks:** macOS local process memory state simulator producing mock process memory dumps.

---

## 5. Experiment Proposal
Build a prototype acquisition module that:
1.  Is triggered when a process attempts suspicious activities (e.g., calling `ptrace` on system processes, loading unlinked dynamic libraries).
2.  Attaches to the process using `ptrace` and reads `/proc/<pid>/maps` to discover segments with Writable & Executable (`rwx`) permissions or unlinked files.
3.  Reads target memory segments via `/proc/<pid>/mem` and writes them to a forensic dump folder.
4.  Scans the dump file using YARA rules matching credential harvesting tools (e.g., Mimikatz, gcsdump).

---

## 6. Metrics & Performance Budget
*   **Acquisition Speed:** Must dump target segments in **< 150 milliseconds**.
*   **Disk Footprint:** Dump size must be restricted to non-shared writeable/executable segments (target: **< 10 MB** total dump size per process).
*   **System Impact:** Suspends target execution via `SIGSTOP` during dump to prevent race conditions, then resumes with `SIGCONT`.

---

## 7. Evidence Required
*   Forensic report logs detailing segment ranges, permission flags, mapped libraries, and target strings.
*   An output file `dump_<pid>.bin` containing verified extracted payloads.

---

## 8. Validation Gate
1.  **Extraction Verification:** Compile a test application that writes a specific signature string (e.g. `MY_SECURE_TOKEN_555`) to a heap-allocated variable. Trigger the Forensic Snapshot Runtime and assert that the exact string is found in the output binary dump file.
2.  **Safety Check:** Confirm that dumping a massive process (e.g. web browser) does not dump shared system library pages (`libc.so`), keeping the size below the 10 MB budget.
