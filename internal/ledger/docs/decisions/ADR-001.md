---\nStatus: Implemented\nImplementation: 100%\nConfidence: Proven\n---\n# ADR-001: Versioned Hashing Schemas

## Context
When data properties are added to `LedgerEntry` (such as V2 state fields), historical block hashes must not break.

## Decision
We prefix hashing operations with a 32-bit big-endian `HashSchemaVersion`. This allows older blocks to be hashed using the V1 rules while newer blocks use V2 rules.

## Consequences
- **Pros**: Backward compatibility; smooth migration.
- **Cons**: Hashing functions need conditional branches based on schema versions.
