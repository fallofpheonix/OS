# Research backlog: R001 - Syscall & Phoenix Trace Telemetry

## 1. Metadata
*   **Experiment ID:** R001
*   **Subsystem:** Kernel / eBPF Telemetry
*   **Priority:** P0 (Crucial Telemetry Foundation)
*   **Validation Status:** Proposed (Pending VM testing)
*   **Risk Level:** Low
*   **Pilot Mapping:** Phoenix MVP Telemetry Agent (`09_telemetry/collectors/`)

---

## 2. Objectives
Establish a low-overhead system call monitoring mechanism and design a real-time process lineage graph builder to identify abnormal parent-child process relationships.

---

## 3. Threat Path
*   **Attack Vectors:** Remote Code Execution (RCE) resulting in a system daemon spawning an unauthorized shell (e.g., `apache` -> `sh`), privilege escalation exploits, and process hollowing.
*   **Threat Assumptions:** Attackers will attempt to bypass monitoring by renaming executables, spoofing command line arguments in memory, or orphan-grouping processes to sever the parent-child relationship.

---

## 4. Telemetry Source
*   **Production hooks:** eBPF tracepoints (`tracepoint/syscalls/sys_enter_execve`, `tracepoint/sched/sched_process_fork`, `tracepoint/sched/sched_process_exit`).
*   **Simulation hooks:** macOS local mock log generator streaming system event states to the Phoenix Bus.

---

## 5. Experiment Proposal
Build a prototype eBPF agent that:
1.  Hooks process forks and executions.
2.  Populates an in-kernel BPF map tracking the active process lineage (PID to PPID).
3.  Streams event payloads to user space via a BPF ring buffer.
4.  Processes the stream in user space to print a real-time ASCII process tree.

---

## 6. Metrics & Performance Budget
*   **Telemetry Latency:** Hook execution to ring buffer write must be **< 5 microseconds**.
*   **Resource Budget:** CPU usage of the telemetry agent must stay **< 3%** under normal loads (< 1000 processes spawned per min).
*   **Max Drop Rate:** **0%** drops during sustained test spikes of up to 10,000 process forks per second.

---

## 7. Evidence Required
*   JSON logs matching the schema specified in `RFC-001`, proving correct identification of PIDs, PPIDs, execution paths, arguments, and calling users (UIDs/GIDs).
*   Successfully rendered process lineage trees demonstrating correct relationships (e.g. `nginx (100) -> bash (101) -> curl (102)`).

---

## 8. Validation Gate
1.  **Correctness:** Execution of a nested script (`bash -> python -> curl`) must trigger exactly matching JSON events for each process in the tree.
2.  **Robustness:** Daemonized/orphaned processes must retain their actual parent PPID links, validated by verifying the lineage remains connected even after the original parent shell exits.
