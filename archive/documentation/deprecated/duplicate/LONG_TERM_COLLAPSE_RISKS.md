# Long-Term Collapse Risks

If Astraeus continues its current architectural trajectory, it will face systemic collapse across several vectors as codebase size, session length, and autonomy scale.

## 1. Event Storage Explosion & Memory Fragmentation
Because Astraeus relies on infinite, append-only JSONL files per run, and massive file-copy snapshots per mutation phase, a long-running autonomous agent (e.g., maintaining a repository for weeks) will generate terabytes of redundant filesystem copies and gigabytes of JSON text.
**Collapse Vector:** The host machine will run out of inodes or disk space. Furthermore, reading the `events.jsonl` file sequentially into memory (`read_all`) to hydrate `RunState` will eventually exceed process memory limits.

## 2. Distributed Synchronization Failure
The roadmap implies scaling to distributed workers. The current architecture strictly couples state to local disk paths (`data_dir / artifacts / run_id`).
**Collapse Vector:** If Astraeus is deployed to Kubernetes or AWS ECS, pods will lack shared state. Workers will attempt to read local JSONL files that do not contain events generated by other workers, leading to massive state desynchronization and split-brain execution where different nodes believe they own the same task.

## 3. Ontology Drift and Replay Incompatibility
`RunState` and `Event` schemas are currently serialized directly to JSON via Pydantic. There is no schema versioning mechanism implemented.
**Collapse Vector:** As Astraeus evolves and adds fields to `RunState` (e.g., changing `task.retry_count` to an object `task.retry_metadata`), attempting to `ReplayEngine.reconstruct_state()` on a log from 3 months ago will throw a `ValidationError`. The historical record of the system will become permanently unreadable.

## 4. Temporal Fragmentation (The Rollback Illusion)
The `RollbackEngine` currently only rolls back local files. It has no mechanism for tracking or rolling back database migrations, remote API calls (e.g., a deployed AWS lambda function), or pushed Git commits.
**Collapse Vector:** If an agent successfully pushes code to a staging branch, runs a database migration, and then encounters a `CRITICAL` failure, Astraeus will roll back the local files but leave the external database migrated. The local codebase and the remote state will be permanently fractured.

## 5. Entropy Accumulation
Because the agent uses `asyncio.to_thread` for LLM calls with naive `try/except` retries, minor hallucinations (e.g., adding an unused import, changing a variable name slightly) that pass the strict `python_syntax` check will accumulate in the repository.
**Collapse Vector:** Over thousands of autonomous iterations, the codebase will degrade into "spaghetti code" that compiles but is unmaintainable by humans. The Semantic Topology Engine will bloat as it maps increasingly convoluted, useless AST nodes, eventually stalling the orchestrator.
