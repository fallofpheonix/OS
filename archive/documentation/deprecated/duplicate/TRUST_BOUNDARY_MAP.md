# TRUST BOUNDARY MAP

## 1. Filesystem Trust Boundaries
- **Boundary:** `TransactionRunner` (staging -> project_root)
- **Component:** `runtime/mutation_sandbox.py`, `transactions/runner.py`
- **Weakness:** The filesystem operations inherently trust the `DiffPlan` outputs generated by models. The path restriction logic (`startswith(project_root)`) can be bypassed via symlink dereferencing inside the `shutil.copy2` / `shutil.copytree` standard libraries if a symlink exists inside the project pointing outside.
- **Access Level:** High. Directly mutates local files.

## 2. Orchestration Trust Boundaries
- **Boundary:** `CommandRiskEngine` and `ExecutionSandbox`
- **Component:** `runtime/risk_engine.py`, `runtime/sandbox.py`
- **Weakness:** The orchestrator delegates execution safety to regex-based string matching (`CommandRiskEngine.evaluate()`). The boundary between untrusted model output (shell commands) and host execution (`subprocess.run(shell=True)`) is extremely porous.
- **Access Level:** Critical. Permits arbitrary RCE on the host OS.

## 3. Memory Trust Boundaries
- **Boundary:** Event Bus and Replay Engine
- **Component:** `events/event_bus.py`, `runtime/replay.py`
- **Weakness:** Memory relies on append-only JSONL files without cryptographic signatures. The system assumes any data read from `events.jsonl` or `run.json` was legitimately generated by the engine.
- **Access Level:** Moderate. Allows state poisoning and replay hijacking.

## 4. Model Interaction Boundaries
- **Boundary:** `OllamaClient` HTTP Interface
- **Component:** `models/ollama.py`
- **Weakness:** HTTP plaintext communication over localhost. The orchestrator fully trusts the LLM responses. Any repository content read by the LLM acts as an implicit trust boundary (prompt injection vector).
- **Access Level:** High. Dictates orchestration logic and mutation planning.

## 5. Event Ingestion Boundaries
- **Boundary:** `EventBus`
- **Component:** `events/event_bus.py`
- **Weakness:** In-process event subscription and file-based JSONL dumping. No strict schema validation against malicious payloads beyond basic Pydantic types. An attacker with filesystem access can append fabricated events to alter run history.
