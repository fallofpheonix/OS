---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Cognition Control Theory (SPEC)\n\n> This specification defines the control loops, goal arbitration, and resource allocation models for PhoenixMind.\n\n## 1. Goal Arbitration\n\nPhoenixMind operates on a multi-objective optimization model with the following priority hierarchy:\n\n1. **Safety (Warden-Enforced)**: Prevent invariant violations. Weight: $\infty$.\n2. **Integrity (Governance-Enforced)**: Maintain Ledger and Replay consistency. Weight: $10.0$.\n3. **Performance (Mission-Enforced)**: Achieve objective targets. Weight: $5.0$.\n4. **Evolution (Self-Enforced)**: Improve internal models and logic. Weight: $1.0$.\n\n## 2. Attention Model (Salience-Based)\n\n- **Focus Buffer**: Only $N$ entities or events can be in the "active" reasoning buffer at once.\n- **Salience Score**: $S = \text{Novelty} \cdot \text{Impact} \cdot \text{Proximity}$.\n- **Pre-emption**: A P0 event (S1 failure) immediately clears the focus buffer to prioritize recovery reasoning.\n\n## 3. Resource Allocation\n\n- **Compute Budget**: Max CPU% and memory allocated to Cognition layer is throttled by the `Platform` layer based on system health.\n- **Task Slicing**: Long-running reasoning tasks must be yield-able (re-entrant) to allow for real-time responsiveness to events.\n\n## 4. Conflict Resolution\n\n- **Policy-Based**: If two goals conflict (e.g., Performance vs. Integrity), the arbiter selects the path with the highest weighted reward according to the `docs/governance/POLICIES.md`.\n- **Warden Override**: If any goal arbitration result would violate a `BOUNDARY_RULE`, the Warden halts the reasoning path.\n\n--- \n*Refer to [REWARD_MODEL.md](./REWARD_MODEL.md) for reward function details.* \n
