---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Game Replay Specification\n\n> This document defines the laws and format for Game Replays, ensuring they remain the authoritative source of truth for game history.\n\n## 1. Replay Invariants\n\n| ID | Invariant | Description |\n| :--- | :--- | :--- |\n| **REP-001** | **Replay is Authoritative** | If a replayed state differs from the live state recorded at that tick, the replay is correct and the live state was corrupt. |\n| **REP-002** | **Full Traceability** | A replay must contain every input event and external influence (e.g., RNG seeds) required to rebuild the state. |\n| **REP-003** | **Immutable History** | Once a replay block is finalized, it cannot be modified. |\n\n## 2. Replay Format\n\n### 2.1 Header\n- `version`: uint32\n- `genesis_hash`: string (Hash of the initial world state)\n- `initial_seed`: uint64\n- `metadata`: Map<String, String>\n\n### 2.2 Event Stream\n- `tick`: uint64\n- `event_type`: EventType\n- `payload`: Bytes (Event-specific data)\n- `signature`: Bytes (Identity signature of the actor)\n\n### 2.3 Periodic Snapshots\n- To enable fast seeking, full world state snapshots must be embedded every `N` ticks (e.g., 600 ticks / 10 seconds). \n\n## 3. Verification Protocol\n\n- **Hash Chaining:** Each replay event/block must contain the hash of the previous one.\n- **Merkle Proofs:** State snapshots must be Merkle-rooted to allow verification of specific entity states without replaying the entire stream. \n\n--- \n*Refer to [docs/MASTER_INVARIANTS.md](../../docs/MASTER_INVARIANTS.md) for global replay laws (INV-001).* \n
