---\nStatus: Draft\nImplementation: 0%\nConfidence: High\n---\n# Game Network Protocol (SPEC)\n\n> This document defines the protocol for game state synchronization and player input.\n\n## 1. Transport Layer: QUIC\n\n- **Reliability**: QUIC provides built-in stream-level reliability and congestion control. \n- **Multi-Streaming**: Distinct streams for `Input`, `StateDelta`, and `AssetTransfer` to prevent head-of-line blocking.\n- **Security**: Mandatory TLS 1.3 encryption for all packets.\n\n## 2. Custom Reliability Layer (for UDP fallback)\n\nIf raw UDP is used, the following mechanisms must be implemented:\n- **Sequence Numbers**: Every packet contains a monotonically increasing `SeqNum`.\n- **Ack Model**: Receivers emit `ACK` packets for received sequence ranges.\n- **Resend Strategy**: Senders maintain a sliding window of un-ACKed packets and retransmit after $RTO$ (Retransmission Timeout).\n\n## 3. Message Serialization\n\n- **Protobuf**: All network messages are serialized using Protocol Buffers for cross-platform compatibility.\n- **Delta Compression**: For `StateDelta` messages, only the XOR diff of entity components is sent.\n\n## 4. Latency Mitigation\n\n- **Client-Side Prediction**: Clients simulate local movement immediately.\n- **Server Reconciliation**: If the server-authoritative state differs from the client's prediction, the client must snap back to the server state and re-simulate intermediate inputs.\n\n--- \n*Refer to [REPLAY_SPEC.md](./REPLAY_SPEC.md) for synchronization laws.* \n
